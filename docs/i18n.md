# Internationalization (i18n) Developer Guide

UniOps provides full dual-language support in Vietnamese (`vi`, default) and English (`en`). It is implemented using a zero-runtime-dependency typed dictionary system that provides compile-time key verification with TypeScript.

---

## 1. File Structure

All frontend translation logic and dictionaries live in `frontend/src/i18n/`:

```text
frontend/src/i18n/
  vi.ts          // Source dictionary: defines Vietnamese UI text and dictionary shape
  en.ts          // English dictionary: strictly satisfies the Dictionary type
  types.ts       // Locale, Dictionary, and typed sub-dictionaries
  index.tsx      // LocaleProvider, useT(), useLocale(), LanguageSwitcher component
  i18n.test.tsx  // Parity, enum coverage, error resolution, and leak tests
```

---

## 2. Core Principles & Rules

### Rule 1: Typed Dictionary Parity
`vi.ts` is the source of truth for the dictionary shape. The dictionary interface is defined in `types.ts` as `Dictionary`. In `en.ts`:
```ts
export const en = {
  ...
} satisfies Dictionary;
```
If a key is missing or mistyped in `en.ts`, TypeScript rejects the build at compile time (`npm run build`).

### Rule 2: Complete Enum Coverage
All domain enums (`OrderStatus`, `AccountingStatus`, `PaymentStatus`, `SyncRunStatus`, `Role`, `ExceptionCategory`) are represented as exhaustive records:
```ts
status: Record<OrderStatus, string>;
```
Adding a new enum variant in `types.ts` without corresponding entries in both `vi.ts` and `en.ts` triggers a compile error.

### Rule 3: Error Code Flow
Handled backend exceptions return structured error JSON:
```json
{
  "code": "ORDER_HAS_LINKED_INVOICES",
  "params": {},
  "detail": "cannot cancel an order with linked invoices; unlink all invoices first"
}
```
1. Backend raises `ApiError(status_code=..., code=..., detail=..., params=...)` (defined in `backend/app/errors.py`).
2. Client `frontend/src/api.ts` parses the JSON and throws `ApiError`.
3. Handlers call `formatApiError(err, t, locale)`:
   - If `err.code` is recognized in `t.errors`, the localized message is returned.
   - If unknown or network failure: `t.errors.generic` or `t.errors.networkFailure` is shown.
   - In Vietnamese, English `detail` is never shown as main alert text (preserved in `.detail` or tooltip for debugging).

### Rule 4: Never Translate Data
Never translate domain or business data:
- Customer names, tax codes, product names and codes.
- Invoice numbers, invoice series, EasyBooks IDs, order numbers.
- Raw logs, which appear only inside a collapsed "Technical details" (`Chi tiết kỹ thuật`) disclosure.

Dates, currencies (`₫`), and numbers always follow `vi-VN` conventions in both languages (e.g., `DD/MM/YYYY`, comma decimals, `DD/MM` due dates).

Date fields use `DateInput` (`frontend/src/components/DateInput.tsx`), never `<input type="date">`: the native input follows the operating system's locale, so an English Windows would show `mm/dd/yyyy`. Quantities go through `quantity()` in `format.ts`, so a stored `1000.0000` reads `1.000`.

### Rule 5: One Language per Screen
A Vietnamese screen contains no English words, and an English screen no Vietnamese words. Only proper nouns such as EasyBooks and UniOps stay unchanged.

Never render backend free text or raw enum codes (`MANUAL`, `DELIVERED`, `NO_PAYMENT_SOURCE`) directly. The backend sends codes or bare identifiers (an invoice reference is `1C26TSH/105`, not `Invoice 1C26TSH/105`), and the frontend maps codes through the dictionaries. Text that cannot be translated, such as EasyBooks error messages, goes behind a translated headline and a collapsed technical-details disclosure.

## 3. How to Add a New UI String

1. **Add key to `types.ts`**:
   Find the relevant section in `types.ts` (e.g., `orders`, `finance`, `common`) and declare the key:
   ```ts
   export interface OrdersDict {
     ...
     exportLabel: string;
   }
   ```
2. **Add translation to `vi.ts`**:
   Add the Vietnamese text according to `docs/glossary-vi.md`:
   ```ts
   exportLabel: "Xuất dữ liệu",
   ```
3. **Add translation to `en.ts`**:
   ```ts
   exportLabel: "Export data",
   ```
4. **Use in component**:
   ```tsx
   import { useT } from "../i18n";

   export function MyComponent() {
     const t = useT();
     return <button>{t.orders.exportLabel}</button>;
   }
   ```

If the string requires dynamic parameters, use a function:
```ts
// types.ts
selectedCount: (n: number) => string;

// vi.ts
selectedCount: (n: number) => `Đã chọn ${n} mục`,

// en.ts
selectedCount: (n: number) => `Selected ${n} item${n === 1 ? "" : "s"}`,
```

## 4. Running Verification & Parity Tests

The test suite runs with Vitest:

```bash
# Run i18n unit tests (parity, enums, error rendering, English leakage check)
npm --prefix frontend test src/i18n/i18n.test.tsx

# Run full frontend test suite
npm --prefix frontend test
```

### What `i18n.test.tsx` validates:
- **Recursive Parity**: Ensures every key path in `vi` exists in `en` and vice-versa, with non-empty string values and callable parameter functions.
- **Enum Parity**: 100% variant coverage for all 6 domain enums.
- **Backend Error Code Parity**: 100% coverage for all 31 backend `ApiError` codes.
- **Locale Resolution**: Fallback from `localStorage` to `"vi"`, storage error handling, and immediate dynamic switching without reload.
- **English Leakage Check**: Renders components under `vi` with mock data and asserts no English dictionary tokens appear in DOM text or `aria-label` attributes.

---

## 5. Known Limitations

1. **Storage Scope**: The locale preference (`uniops.locale`) is stored in the browser's `localStorage`. User preferences do not synchronize across different devices or browsers because per-user preferences are not stored on the server.
2. **Backend Messages & Logs**: Server logs, CLI output, and HTTP `detail` fields remain in English for auditability and developer troubleshooting.
3. **Vietnamese Glossary Approval**: Terms in `docs/glossary-vi.md` are currently draft recommendations awaiting final sign-off from the business owner and chief accountant prior to broad deployment.
